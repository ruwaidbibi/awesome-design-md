# Example output

Three real businesses, taken through the pipeline against live Google Places
data. They are here so the output is visible without running anything, and
because they are the **regression baseline**: the QA stage described in
`../docs/pipeline-plan.md` will be tested by re-rendering these and checking
they still pass.

| Folder | Business | Design system | State |
|---|---|---|---|
| `k-cuts-barbershop/` | K Cuts Barbershop, Jacksonville FL — 5.0★, 317 reviews | ferrari | 2 pages |
| `sippers-coffeehouse/` | Sippers Coffeehouse, Jacksonville FL — 4.4★, 744 reviews | intercom | 2 pages |
| `blessed-hands-barber-parlor/` | Blessed Hands Barber Parlor, Chicago IL — 5.0★, 282 reviews | — | plan only |

Blessed Hands is deliberately plan-only. The site was never built, because
nobody asked for it — which is the rule written up in the README under
*Nothing is generated unless you ask for it*.

## What to look at

`plan.json` is the interesting file. Every section carries `evidence` naming
what entitles it to exist, and a `confidence` of high, medium or low. Two fields
at the bottom are worth reading before the pages:

- **`ownerTodos`** — what the owner has to supply before the site is honest.
- **`claimsAvoided`** — what a careless generator would have written here and
  this one refused to, with the reason.

Sippers is the clearest illustration. It has a one-star review complaining about
a "grumpy owner". The site never mentions it and, less obviously, never *answers*
it — there is no "friendly service", no "warm welcome" anywhere, because:

> Nothing about service quality or friendliness. Reviews disagree sharply on it,
> and a site that promises a warm welcome is exactly what an unhappy customer
> quotes back at you.

The two barbershops are also worth comparing on naming. K Cuts names no barber
(four reviews name four different people; a wrong or departed name on a homepage
is worse than none). Blessed Hands names Jovanni — but only because *Jovanni The
Barber* is part of the registered business name, not a name lifted from a review.

## Verifying no review text reached a page

The generator is instructed never to quote or closely paraphrase a review. An
instruction is not evidence:

```bash
python3 examples/verify-no-verbatim.py
```

It measures the longest run of words shared between each page and the reviews it
was built from, reading them out of `data/leadsites.db`. Current result: **0
words shared, threshold 5.** Exits non-zero on a violation, so it works as a CI
gate. This is the check that becomes a publish gate in the pipeline plan.

## Provenance

The pages are our own original copy and safe to store. Review text is *not* in
this directory by design — it lives only in the local database, subject to the
30-day caching limit enforced in `src/pipeline/freshness.js`. For the same
reason the interactive demo page is not committed anywhere: it embeds full
review text.

These sites were generated by hand through `npm run brief` and `npm run import`
rather than by the built-in generator, because this environment has no
`ANTHROPIC_API_KEY`. They follow the same prompts and the same rules — the brief
export exists precisely so the two paths cannot drift.
